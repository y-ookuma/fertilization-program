# 野菜施肥設計計算アプリ

土壌分析値と作物ライブラリから、10aあたり（および実際の圃場面積あたり）の目標NPK・石灰(CaO)・苦土(MgO)量と不足量、使用する肥料の袋数を自動計算し、施肥設計書をPNG画像として保存できるWebアプリです。サーバー不要、ブラウザだけで完結します。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面構造（(1)土壌分析 → (2)施肥結果 → (3)施肥量 の3ステップ、手順書・READMEモーダル） |
| `style.css` | デザイン（配色・カード・フロー図・養分カード・肥料入力欄など） |
| `app.js` | 作物ライブラリ・計算ロジック・保存/復元・袋数計算・PNG出力 |
| `crops.json` | 30品目の作物データ（参考用。実際の計算は`app.js`内に埋め込まれた同内容のデータを使用） |
| `icon.png` | ファビコン |
| `README.md` | このファイル |

`index.html` をブラウザで開くだけで動作します。インターネット接続は、Googleフォント、PNG出力用ライブラリ（html2canvas）、README表示用のMarkdownパーサ（marked.js）の読み込みにのみ必要です。

> ⚠️ README.mdの内容はアプリ内から「📄 README」ボタンで`fetch`して表示しています。`index.html`をローカルファイルとして直接開く（`file://`）とブラウザの制限で読み込みに失敗する場合があります。その場合は簡易ローカルサーバー（例: `python -m http.server`）経由で`http://`として開いてください。

## 使い方（3ステップ）

画面上部の「土壌分析 → 分析結果と肥料投入量 → 施肥設計書」の順に進みます。

### (1) 土壌分析

1. **① 栽培作物の選択**：プルダウンから作物を選ぶと、その作物の基準養分吸収量・標準元肥比率がライブラリから読み込まれます。
2. **② 土壌分析結果入力**：pH、EC、CaO（石灰）、MgO（苦土）、K2O（加里）、トルオーグ燐酸、CEC、塩基飽和度、石灰/苦土比、苦土/加里比、(11)推定硝酸態窒素を入力します。(11)が分かる場合は入力してください。未入力の場合はECから自動推定します。
3. 「🌾 施肥計算をする」を押すと (2) が展開されます。

### (2) 施肥結果

1. まず、N・P・K・石灰(CaO)・苦土(MgO) の「目標値・残存量・不足量」カードと、窒素算定方法・堆肥・石灰苦土資材のアドバイスが表示されます。
2. **③ 圃場**：圃場名（任意のメモ）と、圃場面積を㎡・a・haのいずれかで入力します。
3. **④ 使用する肥料（最大8種類）**：肥料名・N/P2O5/K2O/CaO/MgO(%)・1袋の重量(kg)・今回投入量(kg)を入力します。「📂 肥料一覧CSVを読み込む」でお手元の肥料一覧CSV（例：[JAさいたま肥料一覧.csv](https://github.com/y-ookuma/fertilization-program/blob/main/JA%E3%81%95%E3%81%84%E3%81%9F%E3%81%BE%E8%82%A5%E6%96%99%E4%B8%80%E8%A6%A7.csv)）を読み込むと、各行に肥料選択プルダウンが表示され、肥料名を選ぶだけでN/P2O5/K2O/CaO/MgO(%)・1袋の重量(kg)が自動入力されます（CSVに列がない項目は空欄のままです）。
4. 「🧮 投入量を計算する」を押すと、面積に応じて目標値・不足量が再計算され、肥料ごとの使用量・袋数、8種類を合算した目標・投入・過不足が表示されます。
5. **特筆事項（任意・400文字まで）**：前作の残肥状況や排水の悪さなど、数値化しにくい気づいた点があれば自由に記入できます（未入力でも構いません）。
6. 「✅ 施肥設計完了」を押すと (3) が展開されます。

### (3) 施肥量（施肥設計書）

圃場名・作物名・面積、土壌分析結果（各項目には目安値との過不足バッジ付き）、目標／不足／投入量（N・P・K・石灰・苦土）、使用した肥料の詳細、堆肥のめやす、特筆事項（入力した場合のみ）がまとめて表示されます。栽培作物名の右側には作成日が表示されます。「🖼️ 結果をPNG保存」「📄 結果をPDF保存」で、A4のレイアウトに合わせて画像またはPDFとして保存でき、栽培作物名の右の作成日・特筆事項もそのまま出力されます（右下にはライセンス表記が別途入ります。PDFは内容が1ページに収まらない場合、自動的に複数ページに分割されます）。

### その他のボタン

- **🌱 作物別基肥一覧**：ライブラリに登録された30品目すべての基肥目標量（N・P2O5・K2O、10aあたり）を一覧表示します。
- **📖 手順書 / 📄 README**：それぞれ操作手順、詳しい計算式やQ&amp;Aを表示します。

### パラメータの保存・復元

- 「💾 パラメータを保存」：ファイル名を指定して、作物・土壌分析値・圃場名・面積・8種類の肥料情報・特筆事項をまとめて`.json`ファイルとしてダウンロードします。
- 「🔁 パラメータを復元」：保存済みの`.json`ファイルを選択して読み込みます。ページ上部・下部どちらのボタンからも同じ操作ができます。

## 計算式の詳細

このアプリの計算はすべて `app.js` 内で完結しています。以下は実際に使われている式です。

### 1. 目標成分量（N・P2O5・K2O）

作物ライブラリの「養分吸収量」に「標準元肥比率」を掛けた値を、その作物の目標施肥量（10aあたり）とします。

```
目標N   = 養分吸収量N   × 標準元肥比率N
目標P2O5 = 養分吸収量P2O5 × 標準元肥比率P2O5
目標K2O  = 養分吸収量K2O  × 標準元肥比率K2O
```

- **養分吸収量**：作物が収穫までに吸収する総量のめやす（品目ごとにライブラリで定義）。
- **標準元肥比率**：吸収量のうち「元肥（植付け前に施す分）」でまかなう割合。追肥中心の作物ほど小さく（例：トマト0.3）、生育期間が短く一度に施肥する葉物ほど大きく（例：ホウレンソウ0.7）設定しています。

### 2. 目標成分量（石灰CaO・苦土MgO）

石灰・苦土は、一般的な土壌診断の目安値を基準値として使用します。

```
目標CaO(mg/100g) = 300（目安値）
目標MgO(mg/100g) = 40（目安値）
目標CaO(kg/10a) = 300 × 0.15 = 45
目標MgO(kg/10a) = 40  × 0.15 = 6
```

### 3. 窒素の残存量 ―「(11)推定硝酸態窒素」優先、未入力時はEC（電気伝導度）による推定

土壌分析の(11)「推定硝酸態窒素(mg/100g)」に値が入力されている場合はその値を優先して使用します。この項目が未入力の場合のみ、電気伝導度(EC)の測定値から残存窒素量を推定します。

```
【(11)推定硝酸態窒素が入力されている場合】
残存N(kg/10a) = (11)推定硝酸態窒素(mg/100g) × 0.15

【(11)が未入力の場合（ECから推定）】
推定硝酸態窒素(mg/100g) = EC(mS/cm) × 80
残存N(kg/10a) = 推定硝酸態窒素(mg/100g) × 0.15
```

- (11)に実測値（または他の方法で推定した値）を入力すると、その値がそのまま計算に使われます。もっとも精度が高い方法です。
- (11)が空欄の場合のみ、ECからの簡易推定に切り替わります。係数「80」は、EC(mS/cm)と土壌中の硝酸態窒素濃度の間に見られる一般的な傾向を踏まえた簡易換算係数です。実際の関係は土性・水分状態・抽出方法（1:5水抽出など）によって変わるため、あくまで参考値です。
- (11)・ECの両方が未入力の場合は、仮の値として EC = 0.3 mS/cm を用いて計算します。
- (2)施肥結果の「窒素(N)残存量の算定方法」アドバイスカードに、実際にどちらの方法で計算したか（実測値／EC入力値／EC仮定値）が表示されます。

### 4. 土壌残存量換算（P2O5・K2O・CaO・MgO）

入力された土壌分析値から、すでに土壌中にある養分を「元肥として節約できる量」に換算します。

```
残存P2O5 = 入力トルオーグ燐酸 × 0.15
残存K2O  = 入力K2O          × 0.15
残存CaO  = 入力CaO          × 0.15
残存MgO  = 入力MgO          × 0.15
```

> ⚠️ 係数（0.15）はmg/100gをkg/10aの元肥節約量に大まかに換算するための簡易係数で、土性（砂土・壌土・粘土）や作土深によって変わります。実運用では地域・JAの施肥基準にある換算係数に置き換えてください。

### 5. 不足量（設計施肥量）

```
不足X = max(0, 目標X − 残存X)   ※X = N, P2O5, K2O, CaO, MgO
```

土壌にすでに十分量がある場合はマイナスにならないよう0未満は切り捨て、カード上に「✅ 目標量に到達しています」と表示します。

### 6. 圃場面積による換算

目標・残存・不足の各値は、上記まで「10aあたり」で算出したのち、入力された圃場面積に応じてスケーリングされます。

```
面積スケール = 圃場面積(㎡) ÷ 1,000
目標X（実面積） = 目標X（10aあたり） × 面積スケール
残存X（実面積） = 残存X（10aあたり） × 面積スケール
不足X（実面積） = max(0, 目標X（実面積） − 残存X（実面積）)
```

面積が未入力の場合は 1,000㎡（10a）として計算します。㎡・a・haのいずれで入力しても、内部では㎡に統一して計算します（1a = 100㎡、1ha = 10,000㎡）。

### 7. 石灰・苦土資材の選び方（石灰/苦土比）

```
石灰/苦土比 > 8  → 苦土（マグネシウム）が相対的に不足気味 → 苦土石灰（ドロマイト）を推奨
石灰/苦土比 < 3  → 苦土に対して石灰が少なめ → 炭酸カルシウムなど苦土を含まない資材を推奨
3 ≦ 比 ≦ 8     → バランス良好
```

一般的に石灰/苦土比は5:1前後が目安とされていることを踏まえた簡易しきい値です。

### 8. 堆肥のめやす（作物カテゴリー別）

各作物には次の7カテゴリーのいずれかが割り当てられており、カテゴリーごとに固定の目安レンジ（t/10a）を面積スケールで換算して表示します。

| カテゴリー | 該当作物の例 | めやす (t/10a) |
|---|---|---|
| 果菜類 (fruit) | キュウリ、トマト、ナス、スイカなど | 2〜3 |
| 葉菜類 (leafy) | キャベツ、ハクサイ、ホウレンソウなど | 1.5〜2 |
| 根菜類 (root) | ダイコン、ニンジン | 1.5〜2 |
| りん茎類 (bulb) | タマネギ、ニンニク、ネギ | 1.5〜2 |
| いも類 (tuber) | ジャガイモ、サツマイモ、サトイモ、ショウガ | 1.5〜2 |
| 豆類 (legume) | エダマメ、インゲンマメ | 1〜1.5 |
| 多年生 (perennial) | アスパラガス | 3〜4 |

### 9. 使用する肥料・袋数計算（最大8種類）

各肥料について、名称・N/P2O5/K2O/CaO/MgO(%)・1袋の重量(kg)・今回投入量(kg)を入力すると、次のように計算します。

```
投入N   = 今回投入量 × N(%)   ÷ 100
投入P2O5 = 今回投入量 × P2O5(%) ÷ 100
投入K2O  = 今回投入量 × K2O(%)  ÷ 100
投入CaO  = 今回投入量 × CaO(%)  ÷ 100
投入MgO  = 今回投入量 × MgO(%)  ÷ 100
袋数    = ceil(今回投入量 ÷ 1袋の重量)
```

8種類すべての投入量・各成分の供給量を合計し、(6)で求めた実面積の目標・不足量と比較して、過不足（カバーできているか、まだ不足しているか）を表示します。

> ⚠️ 石灰・堆肥・肥料の量はいずれも一般的な栽培指針をもとにした簡易的な参考値です。実際の施用量は、土壌診断結果・地域やJAの施肥基準・圃場の履歴に応じて必ず調整してください。

### 10. 肥料一覧CSVの読み込み（肥料名からの自動入力）

「④ 使用する肥料」欄の上にある「📂 肥料一覧CSVを読み込む」ボタンから、お手元の肥料一覧CSVファイルを読み込むと、8種類の肥料入力欄それぞれに「CSVから選択」のプルダウンが表示されます。プルダウンで肥料名を選ぶと、その肥料のN・P2O5・K2O・石灰(CaO)・苦土(MgO)・1袋の重量(kg)が自動的に入力されます。

- 対応しているファイル形式：CSV（`.csv`）。文字コードはUTF-8・Shift_JIS（CP932）のどちらでも自動判定して読み込みます。
- 見出し行（1行目）の列名は、以下のいずれかであれば自動的に認識します（全角・半角や記号の違いは無視されます）。

| 項目 | 認識する見出しの例 |
| --- | --- |
| 区分（任意・プルダウンのグループ分けに使用） | 区分、分類、category |
| 肥料名（必須） | 名称、肥料名、品名、name |
| N (%) | N、窒素 |
| P2O5 (%) | P、P2O5、りん酸 |
| K2O (%) | K、K2O、加里、カリ |
| 石灰 CaO (%) | 石灰、CaO |
| 苦土 MgO (%) | 苦土、MgO |
| 1袋の重量(kg)（任意） | 1袋の重量、1袋の重量(kg)、袋重量、重量、重量(kg) |

- サンプルとして「[JAさいたま肥料一覧.csv](https://github.com/y-ookuma/fertilization-program/blob/main/JA%E3%81%95%E3%81%84%E3%81%9F%E3%81%BE%E8%82%A5%E6%96%99%E4%B8%80%E8%A6%A7.csv)」に対応しています。このCSVには1袋の重量の列がないため、読み込み後も1袋の重量欄は空欄のままです。必要に応じて手入力してください。
- 数値として読み取れない値（例：「6〜8」のような範囲表記や、「中性」「マンガン0.5%」などの文字列）が入っているセルは、空欄（未入力）として扱われます。
- CSVから自動入力した後も、各項目の数値は通常通り自由に手入力で修正できます。
- 読み込んだCSVの内容は保存されません。ページを再読み込みした場合は、再度CSVファイルを読み込み直してください。

### 10. 土壌分析結果の過不足バッジ（(3)施肥量）

(3)施肥量に表示される土壌分析結果の各項目には、右側に目安値との過不足を示すバッジが色分けして表示されます。

```
差(%) = (測定値 − 目安値) ÷ 目安値 × 100

|差(%)| < 5%   → ✓ 適正（緑）
差(%) < -5%    → ↓不足（赤）：例）↓12%
差(%) > 5%     → ↑過剰（青）：例）↑18%
```

項目ごとの目安値は次のとおりです。

| 項目 | 目安値 | 備考 |
|---|---|---|
| pH (H2O) | 作物のtargetPh（未設定は6.3） | 作物ライブラリの値を使用 |
| EC (mS/cm) | 0.4 | 固定の目安値 |
| 石灰 CaO (mg/100g) | 目標CaO(kg/10a)（面積換算後） | N・P・K・CaO・MgOの目標値と同じ |
| 苦土 MgO (mg/100g) | 目標MgO(kg/10a)（面積換算後） | 同上 |
| 加里 K2O (mg/100g) | 目標K2O(kg/10a)（面積換算後） | 同上 |
| トルオーグ燐酸 (mg/100g) | 目標P2O5(kg/10a)（面積換算後） | 同上 |
| CEC (me) | 15 | 固定の目安値 |
| 塩基飽和度 (%) | 75 | 固定の目安値 |
| 石灰/苦土比 | 5 | 固定の目安値 |
| 苦土/加里比 | 2 | 固定の目安値 |
| 推定硝酸態窒素 (mg/100g) | 目標N(kg/10a)（面積換算後） | 同上 |

- **N・P2O5・K2O・CaO(石灰)・MgO(苦土)の5項目**は、(2)施肥結果で計算済みの目標・残存量（面積換算後、kg/10a単位）を再利用しているため、バッジには`↓12%(3.2kg)`のように不足・過剰のkg量も併記されます。
- **それ以外の項目（pH・EC・CEC・塩基飽和度・石灰/苦土比・苦土/加里比）**は、kgに換算する意味を持たないため、%のみを表示します。
- 目安値はいずれも一般的な栽培指針を参考にした簡易的な基準です。作物や地域によって適正範囲は異なるため、参考値としてご利用ください。

## Q&A

**Q1. 計算結果はそのまま実際の施肥設計に使えますか？**
A. いいえ。窒素残存量がEC由来の簡易推定である点、石灰・堆肥・面積換算の係数がいずれも簡易的な一般値である点から、本アプリはあくまで「試算・学習用のたたき台」です。実際の施肥設計は、お使いの地域・JAの施肥基準や土壌診断結果に基づいて専門家に確認してください。

**Q2. 窒素の残存量はどう決まりますか？硝酸態窒素の実測値は使えますか？**
A. 使えます。土壌分析の(11)「推定硝酸態窒素(mg/100g)」に値を入力すると、その値が優先的に使われます。(11)が未入力の場合のみ、電気伝導度(EC)から`推定硝酸態窒素(mg/100g) = EC(mS/cm) × 80`という簡易式で推定します。

**Q3. (11)・ECの両方が未入力のときはどう計算されますか？**
A. EC = 0.3 mS/cm を仮定して計算します。窒素算定のアドバイスカードに「(11)推定硝酸態窒素・ECともに未入力のため、仮の値で推定しています」という表示が出ます。

**Q4. 石灰(CaO)・苦土(MgO)の目標値の根拠は？**
A. 一般的な土壌診断の目安値（CaO 300mg/100g、MgO 40mg/100g）を採用し、他の成分と同じ簡易係数(0.15)でkg/10aに換算しています。土壌タイプや地域基準によって適正値は変わるため、参考値としてご利用ください。

**Q5. 圃場面積はどの単位で入力すればよいですか？**
A. ㎡・a・haのいずれでも入力可能です。プルダウンで単位を選ぶと、内部で自動的に㎡に統一して計算し、換算結果（㎡／a／ha）が入力欄の右に表示されます。未入力の場合は10a（1,000㎡）として計算します。

**Q6. 圃場名はどこに反映されますか？**
A. (2)施肥結果の「③ 圃場」で入力した圃場名は、「施肥設計完了」を押した後の (3) 施肥量（施肥設計書）の作物バッジとキャプションに反映されます。パラメータの保存・復元にも含まれます。

**Q7. 肥料の量が8種類までなのはなぜですか？**
A. 実際の施肥設計で使う資材（化成肥料・単肥・石灰質資材など）を想定した実用的な上限として8種類にしています。増やしたい場合は`app.js`の`FERT_COUNT`定数を変更し、`index.html`側のフォーム生成ロジック（同じく`app.js`内）で対応可能です。

**Q8. PNG・PDFに保存されるのはどの範囲ですか？また作成日やライセンス表記はどこに入りますか？**
A. (3)施肥量の「圃場名・作物名」「土壌分析結果」「目標・不足・投入量カード」「肥料の詳細」「堆肥のめやす」を含む施肥設計書全体が、A4のレイアウトに合わせて書き出されます。栽培作物名の右側に表示されている作成日はそのままPNG・PDFにも含まれ、右下には下記のライセンス表記が自動で印字されます（PNG・PDFとも共通）。

```
This project is licensed under the BSD 3-Clause License.
Copyright (c) 2026 y-ookuma
```

**Q9. パラメータの保存・復元はサーバーに送信されますか？**
A. されません。保存はブラウザ内で`.json`ファイルを生成してダウンロードするだけ、復元は選択したファイルをブラウザ内で読み込むだけで、外部通信は発生しません（PNG/PDF出力用ライブラリ・フォント・README表示・READMEモーダル用のMarkdownパーサの読み込みのみ、外部CDNへアクセスします）。

**Q10. スマートフォンでも使えますか？**
A. レスポンシブデザインに対応しており、スマートフォンやタブレットのブラウザでも入力・計算・PNG/PDF保存が可能です。

**Q11. 対応している作物を増やしたい場合は？**
A. `app.js`内の`fertilizerLibrary.crops`配列（および参考データの`crops.json`）に、同じ形式（id・name・emoji・category・nutrient_absorption_kg_10a・standard_basal_ratio、必要ならtargetPh）でオブジェクトを追加してください。

**Q12. 「作物別基肥一覧」ボタンでは何が見られますか？**
A. ヘッダーの「🌱 作物別基肥一覧」を押すと、ライブラリに登録された30品目すべての基肥目標量（10aあたりの目標N・P2O5・K2O）を一覧表示するモーダルが開きます。石灰(CaO)・苦土(MgO)の目標値はすべての作物で共通のため、一覧には含まれていません。

**Q13. (3)施肥量に表示される作成日と、PNG/PDFに印字される作成日は同じですか？**
A. はい、同じです。作成日は栽培作物名の右側（施肥設計書の見出し部分）にHTMLとして描画されているため、「施肥設計完了」を押した時点の日付がそのままPNG・PDFにも反映されます。ページを開いたままの状態で日をまたいだ場合は、「施肥設計完了」を押し直すと最新の日付に更新されます。

**Q14. 土壌分析結果のバッジ（↓不足・↑過剰・✓適正）はどうやって決まりますか？**
A. 各項目の測定値と目安値の差を%で計算し、±5%以内なら「✓ 適正」、5%以上低ければ「↓不足」、5%以上高ければ「↑過剰」と判定しています。N・P2O5・K2O・CaO・MgOの5項目は、(2)施肥結果で使っている面積換算後の目標・残存量をそのまま流用しているため、バッジのkg表示も他の計算結果と一致します。目安値の一覧は「計算式の詳細 10.」をご覧ください。

**Q15. PNG・PDFの「A4レイアウト」とは具体的にどういう仕組みですか？**
A. PNG・PDFいずれも、施肥設計書の内容を画面には表示されない複製（A4の横幅・約210mm相当のピクセル幅）に組み直したうえで撮影しています。
- **PNG**：A4の横幅に揃えた1枚の画像として保存します。内容がA4 1ページに収まらない場合は、画像自体が縦に長くなります（複数ファイルには分割されません）。
- **PDF**：A4サイズ（210×297mm）のページとして保存します。内容が1ページに収まらない場合は、自動的に複数ページに分割されます（最終ページのみ内容分の高さになります）。
- 解像度の目安は200dpi相当です。より高精細にしたい場合は、`app.js`内の`EXPORT_DPI`定数を大きくしてください（ファイルサイズは大きくなります）。
